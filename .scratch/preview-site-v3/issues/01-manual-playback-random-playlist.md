# Manual playback and default random Playlist

## Parent

[PRD](../PRD.md) — Preview site v3

## What to build

Change the Preview player so a cold visit loads **all visible Catalog Videos** in a **fresh random order** with shuffle **on by default**, but **does not autoplay**. Remove the mute/unmute affordance entirely — the visitor presses Play to start, as on the legacy homepage.

When a Video ends, advance to the next entry in the current Playlist **only if** the visitor had already started playback during this visit. Do not auto-start the first Video on page load. Prev/Next and end-of-video advance must respect the shuffled sequence for the session. Reloading the page produces a new random order (not persisted across visits).

This supersedes the muted-autoplay behaviour described in the older preview-player-polish PRD for this iteration.

## Acceptance criteria

- [x] Page load: first Video visible, paused, no sound, no autoplay, no mute/unmute control
- [x] Default Playlist is all visible Catalog Videos, shuffled on each page load
- [x] Shuffle is on by default for the full-catalog Playlist
- [x] After visitor presses Play, end-of-video advances within the Playlist (respecting shuffle)
- [x] Reset still restarts the current Video from t=0 only
- [x] Reloading `/preview/` yields a different random order; over many reloads each Video has roughly equal chance of appearing first

### Implementation notes (2026-06-21)

Shipped on `master`. Spec corrections recorded in [PRD D2, D7, D8](../PRD.md).

**Misalignments found during build:**

1. **Sign language filter hid the full catalog** — the player defaulted to the first sign language in the picker, so the initial Playlist was a language subset, not all visible Videos. Fixed: default is **All sign languages** (no filter); see PRD D7.
2. **PHP iframe vs shuffled first Video** — the server-rendered iframe still embeds catalog-order video 0; client shuffle may call `loadVideo` for a different first entry on attach. Brief mismatch possible before the SDK loads; accepted for this slice.
3. **Unembeddable catalog Videos** — two test entries (`1201836589`, `1201836590`) returned Vimeo 403 on embed. An automatic skip-to-next-video fallback was tried and **rolled back**; unembeddable Videos surface the Vimeo error. Catalog hygiene (visibility / Vimeo embed settings) is the fix, not player fallback logic.
4. **Shuffle toggle polish deferred** — shuffle is on by default with `aria-pressed="true"`, but obvious toggle UX and active Playlist label remain in [issue 03](03-shuffle-toggle-playlist-label.md).
